💡 A=1, B=2여도 B가 A의 2배 너비가 되지 않는다 — basis 위에 여분 공간의 1/3, 2/3이 얹히는 것. 전부 같은 너비로 만들려면 basis를 전부 0으로 바꿔 볼 것(= flex: 1, 다음 섹션).


      
basis · width · min/max 상관관계 — 3단계 파이프라인

      
/* 주축 크기가 정해지는 순서 (column이면 width → height로 치환, 나머지 동일) */
1단계  시작 크기:  flex-basis → (auto면) width → (auto면) 콘텐츠 크기
2단계  조정:       시작 크기 ± grow/shrink
3단계  클램프:     clamp(min-width, 계산값, max-width)  /* ← 항상 이긴다 */


      
조합별 결과 사례표 — 컨테이너 600px · 파트너 B는 flex: 1 1 0 + min-w-0 (나머지 흡수)

      
A의 선언                                   시작  →  최종    왜
flex: none; width: 120px                   120  →  120    basis auto → width 채택, grow/shrink 꺼짐
flex: none  (콘텐츠 80px, width 없음)         80  →   80    width도 없으면 콘텐츠 크기
flex: 0 0 100px; width: 80px               100  →  100    basis가 width를 이김 (작아도)
flex: 0 0 100px; width: 120px              100  →  100    basis가 width를 이김 (커도)
flex: 1 1 100px                            100  →  350    100 + free 500 × 1/2 (B와 grow 경쟁)
flex: 1 1 0  (+ min-w-0)                      0  →  300    출발선 리셋 → B와 완전 균등
flex: 1 1 0  (긴 텍스트 400px, min-w-0 없음)    0  →  400    자동 바닥(min-content)이 계산값 300을 이김 → B는 200으로 양보
flex: 1 1 0; max-width: 140px                0  →  140    140에서 동결 → 남은 460은 B가 전부
flex: 0 1 0; width: 80px (텍스트 400px)        0  →   80    바닥 = min(min-content 400, width 80) — width가 바닥 공식으로 재등장

5flex-shrink — 아이콘이 찌그러지는 이유

    
shrink 기본값이 1이라 공간이 모자라면 모든 아이템이 말없이 줄어든다. 컨테이너를 좁혀서 아바타를 찌그러뜨려 볼 것.

    

      

        
        
      

      

        

          
🙂

          
컨테이너가 좁아지면 이 텍스트와 아바타가 함께 줄어든다. shrink: 0을 켜면 아바타는 고정되고 텍스트만 줄어든다.

        

      

      
좁혀 보세요 — 체크 전후의 아바타 모양을 비교


      
shrink 가중치 실험 — 줄어드는 양 ∝ shrink × basis

      

        
        
      

      

        

          
A

          
B

        

      

      
좁혀 보세요 — 아이템에 표시되는 실시간 너비로 B가 훨씬 많이 줄어드는 것을 확인 (shrink 2 × basis 300 → 가중치 600 vs A의 200)

      
/* shrink는 비율에 basis를 곱한 가중치로 분배된다 */
줄어드는 양ᵢ = 부족분 × (shrinkᵢ × basisᵢ) / Σ(shrink × basis)

/* 예: 컨테이너 400px, A(basis 200, shrink 1), B(basis 300, shrink 2)
   부족분 = 500 - 400 = 100,  가중치 A = 200, B = 600, 합 = 800
   A: 100 × 200/800 = 25px 줄어듦 → 175px
   B: 100 × 600/800 = 75px 줄어듦 → 225px   (검산 175 + 225 = 400 ✓) */

      
⚠️ "shrink: 2 = 2배 빨리 줄어든다"는 틀린 직관. 정확히는 "같은 basis일 때 2배"다. 비율에 basis를 곱하는 이유: 순수 비율로만 줄이면 작은 아이템이 먼저 0에 도달해 사라지기 때문에, 큰 아이템이 더 많이 양보하도록 설계됐다.

    

  


  
  

    
6min-width/min-height: auto — flexbox 최대의 함정

    
flex item의 min-width 기본값은 0이 아니라 auto(≈ 콘텐츠 최소 크기). 그래서 ellipsis가 안 먹고 컨테이너를 뚫는다.

    

      

        
        
      

      

        

          URL
          

            https://platform.datumo.com/workspaces/42/applications/7/eval-runs/results?page=1&filter=failed-only&sort=score-desc
          

        

      

      
좁혀 보세요 — 체크 전에는 텍스트가 컨테이너를 뚫고(가로 스크롤 발생), 체크 후에는 … 처리된다

      
/* 실무에서 터지는 구조: 말줄임 요소가 flex item의 "자손"일 때 */
.row   { display: flex; }
.label { flex-shrink: 0; }
.cell  { min-width: 0; }            /* ★ 텍스트를 감싼 flex item — tw: min-w-0 */
.value { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }

      
🔍 말줄임 요소가 곧 flex item 자신이면 min-width: 0 없이도 동작한다 — 자동 min-size는 스펙상 overflow: visible일 때만 적용되는데, 말줄임 세트의 overflow: hidden이 그 조건을 깨기 때문. 함정은 위처럼 중간에 overflow: visible인 flex item(래퍼)이 끼었을 때 터진다.

      
같은 함정, 다른 증상 — 넘침의 모양은 "넘침을 받는 쪽"의 overflow가 정한다

      

        

          
overflow: visible (기본값) — 그냥 뚫고 나와 이웃을 덮는다

          

            

              

                URL
                
https://platform.datumo.com/workspaces/42/applications/7/정eval-runs?page=1

              

              
이웃 콘텐츠 — 체크 전에는 URL이 내 위를 덮는다

            

          

        

        

          
overflow: hidden — 말줄임도 없이 소리 없이 잘린다

          

            

              

                URL
                
https://platform.datumo.com/workspaces/42/applications/7/eval-runs?page=1

              

              
여기는 안 덮이지만, URL 꼬리는 … 표시도 없이 사라졌다

            

          

        

      

      
⚠️ 뚫림 자체는 세 데모 모두 동일하다(row가 min-content 아래로 못 줄어듦) — 증상의 모양만 넘침을 받는 조상의 overflow가 정한다. visible(기본값)이면 그냥 뚫고 나와 이웃 UI 위로 겹치고, auto면 위 데모처럼 가로 스크롤이 생기고, hidden이면 ellipsis도 없이 잘려서 가장 늦게 발견되는 버그가 된다. 위의 min-width: 0 토글 하나가 세 데모를 전부 고친다 — 어느 모양이든 처방은 같다는 뜻.


      
🔥 중첩 flex라면 조상 flex item 체인 전부에 min-w-0이 필요하다. column 방향에서는 같은 문제가 min-height: auto로 나타난다 — "스크롤 영역이 안 생겨요"의 원인. 아래에서 직접 재현.
